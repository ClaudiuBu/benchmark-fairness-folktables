# Fairness Drift as a Model Maintenance Problem

Code and benchmark outputs for the paper

> **Fairness Drift as a Model Maintenance Problem: A Temporal Benchmark on Folktables**
> Claudiu-Cristian Butnaru and Gloria Cerasela Crișan.
> *23rd ACS/IEEE International Conference on Computer Systems and Applications (AICCSA 2026)*, Sharjah, UAE.

Fairness interventions are usually validated once, at development time. This benchmark asks what happens afterwards: a model is trained on 2014 California ACS data and evaluated on every later year up to 2018, while five fairness pipelines are crossed with five routine maintenance policies.

**Main observation.** Maintenance actions are not *fairness-monotone*. On the income task in 2018, threshold recalibration reduces the sex-based demographic-parity gap from 0.034 to 0.008 (−76%) while increasing the equalized-odds gap from 0.027 to 0.062 (+130%). Over the same step, accuracy moves from 0.779 to 0.774 and AUC does not change, so standard performance monitoring would not detect the trade-off.

## Experimental design

| Axis | Levels |
|---|---|
| Fairness pipelines | baseline · reweighing (pre-processing) · demographic-parity post-processing · equalized-odds post-processing · exponentiated-gradient reduction (in-processing) |
| Maintenance policies | frozen · threshold recalibration · last-year retrain · cumulative retrain · cumulative retrain with fixed sample size |
| Tasks | `ACSIncome` (> $50K), `ACSEmployment` — California, 2014 development, 2015–2018 evaluation |
| Sensitive attributes | sex (`SEX`), race (`RAC1P`, coded White vs non-White) |
| Repetitions | 20 random seeds per cell, about 2,000 model evaluations in total |
| Model | logistic regression |

All reported values follow the paper's convention (Section III-C):

* each evaluation year is split into four stratified within-year folds, encoded as `YYYY.00/.25/.50/.75` in the result files. The folds are diagnostic strata, not calendar quarters, and a calendar-year value is the mean over the four folds;
* 2014 values come from the development hold-out;
* each sensitive attribute is read from the run configured for that attribute (one run per task × attribute);
* uncertainty is a 95% t-interval over the 20 seed-level estimates;
* metrics are unweighted Folktables sample metrics, not ACS population estimates.

## Repository layout

```
configs/                      experiment and table configurations
  folktables_benchmark_temporal*.yaml   the four runs reported in the paper
  smoke_test.yaml                       small configuration for a quick end-to-end check
src/benchmark/                data loading, fairness pipelines, maintenance policies, metrics, reporting
  tables/                     LaTeX/CSV table generators
src/fairness.py               fairness gap definitions
run_full_benchmark.py         runs the four paper configurations and regenerates the tables
reproduce/                    scripts for the paper's figures and headline numbers, with their outputs
results/folktables/           outputs of the four runs used in the paper, and the generated tables
```

The four versioned runs:

| Task × attribute | Run directory |
|---|---|
| income × sex | `results/folktables/benchmark_temporal/folktables_benchmark_temporal/20260507_165711` |
| income × race | `results/folktables/benchmark_temporal_race/folktables_benchmark_temporal_race/20260508_111012` |
| employment × sex | `results/folktables/benchmark_temporal_employment/folktables_benchmark_temporal_employment/20260507_232826` |
| employment × race | `results/folktables/benchmark_temporal_employment_race/folktables_benchmark_temporal_employment_race/20260508_173829` |

Each run directory contains the resolved configuration (`config_resolved.yaml`), run metadata, seed-level results per evaluation fold (`benchmark_results_by_year.csv`), and the aggregated summaries with confidence intervals. Plots are not versioned and are regenerated by the runner.

## Installation

Python 3.13 was used for the paper.

```bash
git clone https://github.com/ClaudiuBu/benchmark-fairness-folktables.git
cd benchmark-fairness-folktables
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

All commands are run from the repository root.

## Reproducing the paper

**From the versioned outputs (seconds, no data download).**

```bash
python reproduce/headline_numbers.py               # drift and trade-off numbers, Table III
python reproduce/generate_study_design_figure.py   # Fig. 1
python reproduce/generate_fairness_trajectory_figures.py   # Figs. 2 and 3
```

The table generators read the latest run in each configured results directory:

```bash
python -m src.benchmark.tables.initial_performance_combined configs/initial_performance_combined.yaml   # Table II
python -m src.benchmark.tables.final_delta_summary configs/final_delta_summary.yaml
python -m src.benchmark.tables.fairness_gap_combined configs/fairness_gap_combined.yaml
```

**Quick end-to-end check (under a minute once the data are cached; the first call downloads the 2014–2015 files).**

```bash
python -m src.benchmark_runner configs/smoke_test.yaml
```

**Full benchmark.**

```bash
python run_full_benchmark.py
```

The first run downloads the ACS 1-Year person files for California 2014–2018 through Folktables into `data/` (about 2 GB). Each of the four configurations took 6.5–10.5 hours on an Apple M1 Pro. New runs are written to new timestamped directories, so they never overwrite the versioned outputs. Use `--resume-completed` to skip configurations that already have a complete run.

## Scope and limitations

The benchmark is deliberately narrow so that every number can be audited: one state (California), one model class (logistic regression), a binary race coding, unweighted sample metrics, and descriptive rather than causal analysis. See Section VI of the paper for the full discussion.

## Data

The data come from the U.S. Census Bureau American Community Survey Public Use Microdata Sample, accessed through [Folktables](https://github.com/socialfoundations/folktables) (Ding et al., NeurIPS 2021). The raw data are not redistributed here. Their use is subject to the Census Bureau's terms.
